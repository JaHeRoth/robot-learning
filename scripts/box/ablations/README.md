# Flip ablations

These experiments ran on cloud boxes from 8 to 11 Sept 2026, generated by Claude Code under my direction. The question was why ACT learns the wrist-camera flip task (`flip_wristcam`) so much faster than the original one (`flip`). The two experts differ in several ways at once:

- the wristcam expert pre-rolls the wrist half a turn, so the flip during the carry turns against the base swing instead of with it
- it carries a physical wrist camera, which shows up in the front view
- it jitters speed and trajectory
- it always aims at the same drop-off spot, where the flip expert adds unobservable noise of up to 15 mm per axis
- its shelf is 6 cm deep instead of 11 (no ablation isolates this one)

Most ablations change one of these on one of the two tasks. The datasets and checkpoints are on the Hub; this folder holds the code that made the datasets and the tasks they were trained and evaluated on. On the Hub the wristcam datasets still carry their old name, `so100_flip2_*`.

**The code is only meant to run at the commit tagged `flip-ablations`:**

    git checkout flip-ablations
    pixi install

## How it works

Each module is one ablation. When imported, it patches the main generator, and the eval env where needed, with modified copies of only what it changes: functions, constants, scene files (under `scenes/`). Changed lines in copied functions are marked `# ablation`. Each module also defines its tasks in `TASKS`.

The patches are global, so run one ablation per process.

Generate a dataset (seeds from 0, the published episode count unless you pass `--episodes`):

    python -m scripts.box.ablations.flip_nopj --out-dir outputs/flip_nopj_100

Train or sweep through `run.py`, which adds the ablation's tasks to `scripts.tasks.TASKS` and then runs the given module:

    python -m scripts.box.ablations.run flip_nopj scripts.train --method act \
        --task so100_flip_nopj_100 --chunk-len 50 --n-action-steps 40 --checkpoint-every 2500
    python -m scripts.box.ablations.run flip_nopj scripts.box.sweep_checkpoints outputs/my_act \
        --task so100_flip_nopj_100 --n-seeds 500 --start-seed 800000 --n-action-steps 40 --record 0

How the box runs were set up:

- training seed 0 unless noted
- checkpoints every 2.5k steps
- stopped at 30k steps; the learning rate is constant, so `step_030000.pt` of a longer run is the same model
- success rates are 500-seed sweeps over seeds 800000–800499; the model cards have the 95% intervals

These models use the main tasks and need nothing from here: `act_flip_v1_100_100k` (`so100_flip_100`), `act_flip_v1_10k` (`so100_flip`) and `act_flip_v2_100_frontwrist` / `_1k_frontwrist` (front + wrist).

What this shows:

- **Learning speed.** The clearest difference is early. At 5k steps the flip base scores about 0, while the pre-roll alone gets 0.78, level with the front-only wristcam runs (0.73–0.81). The other changes help less: the bare wrist camera 0.55, no drop-off noise 0.43, jitter 0.18.
- **By 30k steps, single runs mostly don't separate.** Most variants land between 0.77 and 0.96, and the two flip base seeds alone are 5 points apart.

## Caveats

- **Reproducibility.** The datasets were generated on x86-64 Linux and should reproduce bit-exactly there. On Apple Silicon a few episodes drift slightly, by up to 3e-3 rad from the grasp on: seed 1 for the flip datasets, and about 15 in 100 episodes for the wristcam ones. The Mac checks were state/action comparisons against the Hub data. Training does not reproduce bit-exactly at all: GPU nondeterminism, plus some runs were resumed without RNG state.
- **Horizon.** The model cards say horizon 450, but the flip models were evaluated at 300, the flip task's horizon.
- **\* `act_flip_v1_counterroll_wristA`.** The card's numbers come from a second, identically configured run whose checkpoints were never uploaded.
- **† Eval scenes.** `wristcam_nojitter` and `wristcam_pj` make extra random draws when sampling a scene, so the same seeds gave them different scenes from the other wristcam models. Same distribution, not paired.
- **Imputed reward.** On the box the wristcam tasks used −0.012 (now −0.002). This only changes the reward column of the sweeps.
- **`flip_low_rand500`** needs a local copy of `so100_flip` with videos. It uses `scripts/box/merge_lerobot_datasets.py --keep`.
